## 5. Standards for Generated Content

All outputs from the engram-mcp server / Grok (briefings, summaries, analyses, drafts) must follow:

- **Voice:** Direct, concise, optimistic but realistic. No fluff, no corporate-speak. Use "you" when addressing the human. Short paragraphs.
- **Format:** Always Markdown. Use tables for lists/comparisons. Bold key actions. Date-stamp every file `YYYY-MM-DD`. Include "Generated by Grok / engram-mcp on [date]" footer when appropriate.
- **What to Avoid:** Never produce vague "to-do" lists without owners/dates. Never hallucinate facts about your life. Never send communications (email/Slack) without explicit human review flag. Never delete — only archive with timestamp.
- **Length Targets:** Morning briefing < 300 words. Weekly reviews 400-600 words. Queue tasks produce focused artifacts.
- **Structure:** Lead with the answer or most important item. Use bullet lists, checklists, and clear sections.

## 6. Operating Rules (Non-Negotiable)

- **Never Delete:** All content moves to `07 - ARCHIVE/` with timestamped filename (e.g. `2026-05-21-old-note.md`). Storage is infinite; daily operation never touches ARCHIVE.
- **Capture Safety Net:** Zero decisions at capture time. Everything lands in `00 - CAPTURE/` first. Classification happens later via automation or evening review.
- **BRAIN.md is Law:** Every workflow, every MCP tool call, and every manual Grok session starts by reading this file. One update propagates intelligence everywhere.
- **Date Stamps:** Every new note, log entry, generated file uses `YYYY-MM-DD` prefix or ISO date in frontmatter.
- **Logging:** All automated actions and significant manual changes are appended to `03 - SYSTEM/logs/` (e.g. `capture-log.md`, `workflow-runs.md`).
- **Human Review Gate:** The engram-mcp / Grok never sends external communications, posts publicly, or makes irreversible changes without a clear `NEEDS HUMAN INPUT` flag + explicit approval step.
- **Queue Discipline:** Files in `05 - QUEUE/` follow `VERB-TOPIC.md` naming (RESEARCH-xxx.md, PLAN-xxx.md, REVIEW-xxx.md, etc.). Processor consumes and archives them.
- **Anti-Overwhelm:** If backlog panic appears, the system forces a CAPTURE → CLASSIFY → PRIORITIZE flow before any new work. The OS runs even on bad days.

## 9. Sleep Cycles (Memory Consolidation)

**Mechanism**: Periodic offline consolidation. `engram_trigger_sleep(n_passes=3, scope="nightly"|"manual", dry_run=False)`:
- Always starts by reading this BRAIN.md (logged).
- Collects recent context (dailies, briefings, QUEUE, recent ARCHIVE samples, logs).
- Runs N recurrent passes (Pass 1: extract entities/dates/projects/themes/facts; Pass 2: cross-source connections & patterns; Pass 3+: compress to dense Fast Memory Blocks: Knowledge Atoms, Cross-Day Synthesis, Priority Evolution, Signals).
- Writes single artifact `04 - GENERATED/consolidated/YYYY-MM-DD-HHMM-sleep-consolidation.md` (HHMM suffix prevents same-day collisions on manual/ad-hoc triggers; nightly N8N is one-per-day).
- Embeds exact proposed markdown deltas for this file (human reviews + pastes surgically). Never auto-edits BRAIN.md.

**Triggers**: Manual (Grok TUI, `grok mcp` calls, python) or scheduled (N8N "Engram - Nightly Sleep Cycle" at 03:00 cron `0 3 * * *`).
**Output & Wake**: Consolidated index in GENERATED/consolidated/. "Wake": next tools/briefings read fresh live state + may reference the new fast memory artifact. Clears any transient cache notion.
**Logging & Safety**: Every cycle appends to `03 - SYSTEM/logs/system-log.md`. Full traceability via Sources section in artifact. Respects never-delete, 8-folder, GENERATED whitelist, human review gate on all proposals.
**Future**: When XAI_API_KEY available in env, replace heuristic passes with true recurrent Grok calls for richer abstraction (see docker-compose env).
**Rule**: Proposals always contain "NEEDS HUMAN INPUT". No direct writes to BRAIN.md from sleep (or any tool).

See `engram-mcp/src/engram_mcp/sleep.py` and the N8N workflow `07-nightly-sleep-cycle.json`.
